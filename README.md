### 1. `S1_Prompt_Library_Excerpt/`
* **`S1_Hydrology_Aware_Prompt_Library_Excerpt.md`**: Representative excerpt of the planning system message (`EXPERIMENT_SYSTEM_MESSAGE`) from the hydrology-aware prompt library module (`prompts.py`), including:
  * **S1.1 Core Directives** governing domain-specific plan formulation, data resilience, and execution blocks.
  * **S1.2 JSON Plan Schema** specifying the structured step types (`manual:setup`, `code:api`, `code:script`, `code:cli`, `manual:analysis`) and `llm_edit_instruction` schema.
  * **S1.3 Worked Example** demonstrating USGS NWIS streamflow retrieval and visualization.

### 2. `S2_Iowa_River_Case_Study_Artifacts/`

#### A. End-to-End Plan-to-Paper Session (`14:17:55 UTC`, 87 Provenance Events, Top-Level `S2` Directory)
Complete workspace artifacts generated and logged during the seven-step end-to-end Iowa River case study (USGS station `05454500`, Iowa River at Iowa City, IA; calendar years `2019-2023`, `1,826` daily discharge records):
* **`experiment_plan.json`**: The 7-step structured JSON experiment plan approved at Stage 1 (in which Step 2 already specifies `requests.exceptions.RequestException`, `KeyError`, `IndexError`, and `JSONDecodeError`).
* **`experiment.py`**: The complete 225-line standalone Python analysis script generated and executed during Stage 2 and Stage 3.
* **`provenance.jsonl`**: The complete 87-event machine-readable JSON Lines (`JSONL`) provenance log capturing workspace initialization, `pip freeze` environment capture, step-level LLM calls (`o3-mini`, `mode: "initial_edit"`), human checkpoint approvals (`approve_code_step`), `pyflakes` static analysis checks, subprocess execution telemetry, and Stage 4 LaTeX manuscript drafting and compilation events.
* **`requirements.txt`**: The complete 86-package software environment specification (`Python 3.13.5`) captured automatically via `pip freeze`.
* **`daily_hydrograph.png`** & **`annual_indicators_summary.png`**: The two analytical plots generated by `experiment.py` (corresponding to Figure 8 in the manuscript).
* **`research_paper.tex`**, **`references.bib`**, & **`research_paper.pdf`**: The unedited Stage 4 baseline manuscript draft and compiled PDF (corresponding to Figure 11 in the manuscript), preserved to illustrate the importance of human domain review during Stage 4.

#### B. Earlier Interactive Session (`13:28:26 UTC`, 66 Provenance Events, `earlier_interactive_session_132826_UTC/`)
Complete workspace artifacts from the earlier interactive walkthrough session on the same date (`13:28:26 UTC` to `13:39:04 UTC`, 6-step plan, 10 minutes 38 seconds workspace-to-execution) documented in Section 4.3 and Section 4.6:
* **`provenance.jsonl` (66 events)**: Records workspace setup, five `mode: "initial_edit"` step-generation calls, and the human-initiated conversational code-assistance intervention during Step 3 at **Events 24-25** (`13:33:43.995Z` to `13:34:00.665Z`, `"task": "unified_code_assist_processing_steps"`, `"model_name": "o3-mini"`, `"success": true`), followed by researcher approval at **Event 28** (`13:34:42.746Z`, `"action": "approve_code_step"`, `"step_number": 3`). By contrast, Step 2 (`Events 13-17`) and Steps 4-6 (`Events 30-50`) record only `"mode": "initial_edit"` and `"approve_code_step"` events.
* **`experiment_plan.json` vs. `experiment.py` (254 lines)**: Whereas Step 2 of `experiment_plan.json` (lines 33-34) specified only a generic `except Exception as e:` without a request timeout and Step 3 (`validate_data`, lines 44-45) had no `try/except` block, the finalized `experiment.py` (lines 29-136) rewrote both `fetch_streamflow_data` and `validate_data` *"with extensive error handling"*, adding `timeout=10` on `requests.get(...)` (line 51) and dedicated `except` blocks for `requests.exceptions.RequestException` (line 53), `json.JSONDecodeError` (line 59), and `(KeyError, IndexError)` (line 65).
* **Note on Version 1 JSONL Logging Granularity**: In this prototype version, live unified file diffs and verbatim chat prompts were rendered in Streamlit's in-memory session state during review rather than serialized verbatim inside `provenance.jsonl` (`approve_code_step` logs a 100-character header preview while overwriting `experiment.py` on disk). Consequently, `provenance.jsonl` identifies which step triggered conversational assistance (`unified_code_assist_processing_steps`), while the resulting code changes are verified by comparing `experiment_plan.json` against `experiment.py`.
* **`requirements.txt`**, **`daily_hydrograph.png`**, & **`annual_summary.png`**: The pinned 86-package environment specification and analytical figures produced during the `13:28:26 UTC` session.

## Reproducing the Iowa River Case Study Analysis (Computational Reproducibility)

Because HydroScholar AI exports a standalone Python script (`experiment.py`) alongside its pinned package specification (`requirements.txt`), reproducing the numerical indicators and figures in Section 4.4 does **not** require an active OpenAI API key or LLM connection.

To re-run the analysis locally:

```bash
cd S2_Iowa_River_Case_Study_Artifacts
python -m venv venv
# On Windows:
venv\Scripts\activate
# On macOS/Linux:
# source venv/bin/activate

pip install -r requirements.txt
python experiment.py
```

Running `python experiment.py` queries the live USGS NWIS Daily Values REST API (`https://waterservices.usgs.gov/nwis/dv/`, parameter code `00060`, site `05454500`, `2019-01-01` to `2023-12-31`), validates the 1,826 daily records, computes the calendar-year mean flows, 7-day rolling minimum flows, and peak-flow dates (verified in Table 2 of the manuscript), and regenerates `daily_hydrograph.png` and `annual_indicators_summary.png`.
